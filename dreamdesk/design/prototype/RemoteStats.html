④ 每一项的数据从哪来
项普通模式（RustDesk 视频流）专业模式（专业通道）
网络延时有：RustDesk 测的往返（现在质量监测里的「延迟」）有：专业通道往返（现在的 RTT）
帧延时没有（RustDesk 不带采集时间），不显示有：被控端采集 → 本机上屏的中位数（现在的 e2e）
帧率有有
带宽占用有：现在的「速度」（kB/s 换成 Mbps）有
目标码率有：被控端编码器目标没有，不显示
丢包率没有（走 TCP，不丢包），不显示有：现在是丢包 / 补回个数，要改成比例
无损比例没有，不显示有（1:1 无损显示时）
加密通道有：TCP / UDP、直连 / 中继（现在标题栏盾牌的悬停说明）有
被控端 IP / 控制端 IP要补：连接里有，RustDesk 没交给界面（主控端 Rust 加一个小查询）要补：同左
被控端版本 / 系统有：对端信息里带有
编解码器（硬 / 软）要补：本机解码是硬是软主控端知道、没交给界面；被控端编码是硬是软要它报（我们的私有字段）有（专业通道我们自己的）
编码 / 色度 / 位深有编码、色度；位深没有，不显示有
分辨率有：对端信息里这块屏的尺寸有
采集方式要补：被控端知道（DXGI / GDI / WGC、Linux 的 X11 / PipeWire），要它报（我们的私有字段）要补：专业通道被控端报一下
