# kiosk 版方案（K 系列，2026-10-25）

## 目标

瘦客户机开机显示登录页，用 AD 账号登录后列出这个人被授权的工作站，选一台以专业模式全屏连上；用户看不到 Ubuntu 桌面、
碰不到系统；断了自动接回去。

**10-26 改向**（用户定）：照旧版 DreamDesk 的「登录 → 选工作站」，不再走「座位绑定一台、开机直连」。10-23 的「先绑定、后登录」
是当时分期的选项，用户 10-26 看过后改成直接按人登录；座位绑定从 kiosk 流程里拿掉（服务端的座位绑定和问绑定接口留着不动）。
下面「实施记录」里 10-25 的座位直连记录保留作历史。

## 用户已定（10-26）

- 开机先显示登录页，登录后列出「我被授权的工作站」。界面以旧版为底线（见「界面」）。
- 座位不当被控端；kiosk 安装包让瘦客户机自动上报为座位（服务端预选类型，确认仍由管理员做）。
- kiosk 不另开分支（同一程序 + `--kiosk` + 独立安装包）；要带通用模式（专业模式出问题的退路、会话中切换）；
  通用窗口的工具栏和专业窗口的菜单由用户统一规划，在那之前不动，只去掉 kiosk 下会让窗口找不回来的最小化和退出全屏。
- 系统更新不管，管理员后台处理。

## 用户已定（10-25）

- 装在全新的 Ubuntu 26.04 上：IT 装好系统，再装我们的 kiosk 安装包，包把其余的都配好。不做整机镜像。
- 本机不提供维护入口：维护走远程 SSH，或者重装。
- 用户能主动断开：断开后回状态页，有「重新连接」「关机」。

## 已经具备的

- 服务端：座位登记、管理员确认、绑定工作站、座位凭设备签名要票（真机联调通过）；座位要票的状态码分清了「不是座位」和「座位被拒」。
- 客户端：专业模式（全屏、多屏、HDR、悬浮球、USB 透传、麦克风）、受管连接票、应急票、座位要票。
- 系统：Ubuntu 26.04 + GNOME 50，系统仓库自带 GNOME Kiosk 50.0（和 GNOME 50 同一个 mutter）。

## 组成

1. **系统外壳：GNOME Kiosk**
   - 专用账户 `kiosk`，开机自动登录进 kiosk 会话，会话里只跑我们的程序，程序退出或崩溃自动拉起。
   - 没有桌面、任务栏、终端、文件管理器；切虚拟终端、切窗口等系统快捷键关掉；屏保、锁屏、自动更新弹窗、蓝牙配对弹窗关掉。
   - 选它的理由：和现在的 GNOME 50 共用 mutter，HDR 开关（显示配置 D-Bus 接口）、显示器排布、专业窗口的零拷贝显示都由 mutter 提供，
     已经验证过的东西可以沿用。cage 等更小的合成器，这些都要重新做、重新验证。
2. **开机流程**（新的程序角色 `--kiosk`，kiosk 会话只起它）
   - 10-26 起：登录页（AD 账号）→ 我的工作站列表（`/api/dd/workstations`，带在线、在用）→ 选一台，以用户身份要票、专业模式全屏连上。
   - 掉线：状态卡片显示原因、按退避自动重连同一台；被拒、工作站那边断开：停在卡片上；自己断开：回列表。
   - 10-25 的第一版是「凭设备签名问绑定、以座位身份要票、开机直连」，10-26 拿掉。
3. **悬浮球**：保留现有功能，加「断开（回状态页）」和「关机 / 重启」。其余设置全部内置，不给用户改。
4. **安装包** `dreamdesk-kiosk`（依赖 `dreamdesk-pro`、`gnome-kiosk`、`openssh-server`）：装上后建 `kiosk` 账户，配好自动登录和
   kiosk 会话，关掉不需要的系统组件；卸载时还原。远程维护用 IT 自己的管理员账户 SSH 进来。
5. **安全**
   - `kiosk` 账户没有 sudo、没有终端，程序和系统配置都读写不了。
   - 座位密钥被偷了的后果：能从别处使用这个座位绑定的那台工作站。坐在座位前本来就能用，所以风险不大。
     服务端已经有「同一把公钥从两处报到 → 判为疑似克隆 → 停发票」；再加一条「座位从登记之外的地址要票就告警」。
     磁盘加密做成可选项。
   - 被控端仍然只认连接票，kiosk 这边不存任何口令。
6. **升级**：K1 手动装新包；内网 apt 源自动升级放 K3。

## K1 拆成几步（每步都有机器判据）

| # | 内容 | 机器判据 |
|---|---|---|
| 1 | 座位问绑定：GET `/api/dd/seat/target` 带设备签名（签名现在只挂在 POST 上，要补 GET） | 联调包上问到绑定的那台；没绑定 / 没确认分别拿到对应的原因 |
| 2 | `--kiosk` 角色：问绑定 → 要票 → 专业模式连上；失败重试、断了重连（先不做界面，只做流程） | 瘦客户机上起 `--kiosk`：连上；停服务端 / 关工作站 / 断网后自动恢复，日志可数 |
| 3 | 安装包：建账户、自动登录、kiosk 会话、关系统组件、卸载还原 | 装包和卸包前后系统状态逐项对比；重启后 kiosk 会话里只有我们的进程 |
| 4 | 状态页、悬浮球的「断开」「关机」 | 界面要人看；按钮背后的动作（断开、关机）用命令触发验证 |
| 5 | 锁定：快捷键、屏保、弹窗 | 注入按键看有没有切走；等过屏保时间看有没有锁屏 |
| 6 | 服务端：座位换地址要票告警 | 换个源地址要票，看告警和计数 |

## 实施记录

### 断开、掉线、重试各归谁（10-25）

- **重试只归状态页**（子会话1 审查后改，第一版放在远程窗口里，问题见下）：远程窗口出了连接类错误——连接出错（掉线、工作站
  离线、服务器连不上）、登录被拒（被控端不认票）、要票被拒，以及 kiosk 前没人能填的口令框——不弹提示框、不自己重试，
  把原因交给主窗口（窗口消息 `dd_kiosk_session_ended`）、关掉这个连接；状态页显示原因，按 5、10、20、30、60 秒退避
  **重新问绑定**再连。一次连接撑过 60 秒才断的，退避从头算。
- 第一版让远程窗口自己重试（凡是报错都重、最长 60 秒），审查查出：座位改绑后一直连旧目标、不会重新问绑定；被拒时每次重试都
  要一张票，审计里留一堆被拒或「发票成功却没连上」的记录；还盖掉了 RustDesk「被手动断开不重连」的例外。
- **不自动再连的**：用户自己断开（悬浮球「断开」：远程窗口关了、没交原因）；工作站上的人断开（「Closed manually by the peer」）。
  这两种回状态页显示原因，等用户点「重新连接」。服务端经心跳要断的（「Closed manually by web console」：收回授权、解绑、改绑、
  退役、控制台单独断开都是这一句，被控端不知道为什么断）照常退避后重新问绑定——改绑跟得上；管理员单独断开某个座位，
  它过几秒会连回来，要真停住就解绑或退役。
- 接手后关窗和专业模式关窗同一套收尾（先关会话、移除标签、强制出一帧、按子窗口关闭流程关窗）：专业画面开着时通用窗口是藏着的，
  只移除标签关不掉。
- 没人能答的「要不要改走中继」提示，照提示框里「走中继」按钮做；标题为「Error」的错误（如工作站没有显示器）也交给状态页。
- 要票被拒的提示标题不用「Connection Error」：RustDesk 按那个标题加正文里的英文词判断要不要自动重连，服务端的中文原因
  会被当成可重连（普通受管主控端被拒后会一直重连、一直要票）。
- kiosk 下服务端连不上时不弹应急票口令框、服务端回 404（目标不是受管工作站或这台不是座位）时不走原有口令流程，都直接报错。
- 已知限制：工作站离线时每次重试都会开一次远程窗口、马上关掉，状态页和远程窗口交替出现（最长 60 秒一次）。
  被控端不认票（时钟偏、票钥轮换、工作站重装换钥）时每次重试都签一张票，最多约每分钟一张。
  装过 10-25 下午第一版 kiosk 包（没有 /var/lib/dreamdesk-kiosk 记号）的机器不能直接升级，要先彻底删除再装——只有测试瘦客户机装过，已处理。
- 「是不是 kiosk」读本进程启动参数（`/proc/self/cmdline`）：远程窗口和主窗口在同一个进程、但各自一个 Dart 环境，
  主窗口设的全局变量远程窗口看不到。
- kiosk 页之下照样建原来的主窗口页（不显示）：远程窗口要主窗口应答一套请求（屏幕列表、窗口激活登记等），
  那套应答写在原来的首页里。只换掉首页时远程窗口一开就报「没有这个方法」。

### 安装包（10-25）

- 装法：`apt-get install --no-install-recommends ./dreamdesk-pro-*.deb ./dreamdesk-kiosk-*.deb`。不加 `--no-install-recommends` 时
  apt 会顺带装上 gnome-kiosk 推荐的两个示例会话（搜索机、脚本会话），开机自动登录用不到，但多两个会话入口。
- 会话照 gnome-kiosk-script-session 的结构：wayland 会话文件 → gnome-session 会话 → 用户级 systemd 目标要求 GNOME Kiosk 和
  我们的程序；我们的程序退出或崩溃 2 秒后拉起，不结束会话（官方示例退出就回登录界面）。
- 装包：建 `kiosk` 账户（口令锁住、只能自动登录）、默认会话设成 DreamDesk Kiosk、GDM 自动登录改成它。GDM 设置只动
  自动登录那两行，装包前的两行记在 `/var/lib/dreamdesk-kiosk/`，卸载时换回去，装包后别人改的其它设置不动
  （第一版整份覆盖，会丢掉别人的改动）。本包建的账户也在那里留记号（说明字段可能被改过，不拿它认）；
  已有一个不是本包建的 `kiosk` 账户时停下不装，不动别人的账户。彻底删除（purge）先结束 kiosk 会话再删账户。
- 不卸载切回原来的桌面：管理员 SSH 上去 `sudo dreamdesk-kiosk off`（`on` 切回 kiosk，`status` 看现在和下次开机进什么），
  切完马上重启，加 `--no-reboot` 只改设置。kiosk 不是盖在桌面上的程序，是开机自动登录进的另一个账户、另一种会话，
  停服务只会剩黑屏（程序还会被拉起）；要回桌面只能让 GDM 下次自动登录原来的账户，所以切换就是换那两行。
  关掉后升级本包不会改回 kiosk。装包、卸载改 GDM 设置也走这个命令（卸载在 prerm 里调，卸载后命令就没了）。
  瘦客户机实测（10-25）：off 重启后自动登录进 of3d 桌面、kiosk 没起；on 重启后回到 kiosk 会话。
- 程序连续秒退时 systemd 默认 10 秒内起 5 次就不再拉起，会话只剩黑屏；kiosk 服务去掉了这个上限。
- 开机被登录界面盖住（瘦客户机实测，10-25）：非 GNOME 桌面的会话由 GDM 的会话包装程序代报「画面就绪」，要等 10 秒；
  GDM 在会话报到时也起了个 10 秒计时器，到点没收到就硬关开机动画，前台落回 1 号终端，GDM 在那里另起登录界面、成了前台，
  kiosk 会话被挤到后台（官方 gnome-kiosk-script 会话同样如此）。修法：我们的程序一起来就自己向 GDM 报「画面就绪」
  （系统总线 `RegisterDisplay`，不带参数），和 GNOME 桌面由 gnome-shell 自己报是同一条路。

### 锁定（K1 第 5 步，10-25）

只作用于 kiosk 账户 / kiosk 会话，其它账户照旧：
- **系统自动启动项一个不起**：GNOME 50 的会话管理没有关掉自动启动的开关，它只从 `XDG_CONFIG_DIRS` 下的 autostart 目录找；
  kiosk 会话的会话管理服务（`gnome-session-manager@dreamdesk-kiosk.service`）加一份补丁把它指向本包自带的空目录。
  逐条屏蔽会被以后新装的包绕过，这样不会。
- **挂在所有会话上的用户级单元**（首次登录向导、升级介绍、崩溃报告、升级提示、snap 刷新、使用统计、文件索引）：
  在 kiosk 账户下逐个屏蔽，清单在 `dreamdesk/kiosk/masked-user-units`。它们挂在 GNOME 共用的启动目标上，摘不掉，只能按名屏蔽；
  首次登录向导的「升级介绍」检查的标记带系统版本号，补标记文件下个版本就失效。
- **快捷键、锁屏**：装包时把本包的设置文件编进 kiosk 账户自己的设置库：关掉切终端（Ctrl+Alt+F1–F12）、
  恢复快捷键（Super+Esc）、锁屏、空闲计时。
- **电源键**：会话里不起 GNOME 的媒体键守护进程（它会接管电源键），电源键归系统，按 logind 默认关机。
- 检查：开机后前台是 kiosk 会话、没有登录界面；kiosk 账户下没有自动启动项；设置读出来是上面的值；没有程序接管电源键；
  注入 Ctrl+Alt+F3 / F1 不切走（同一个注入在普通桌面上会切走，证明注入本身有效）。

### 界面（10-26）

- 以旧版 DreamDesk kiosk 界面为底线（用户 10-26 批第一版状态页「黑底一行字」）：深色底配红色霓虹、菱形标识、四角角标卡片、
  旧版的准星过场；用户看过原型（https://claude.ai/artifact/Ri5xc1vit1bKFgX9SsDKXt）后定：版权写江苏原力、保留中英文切换、
  网格地平线这版先不加（星点、地平线一起不加）。
- 技术：Flutter 页面（和连接逻辑同一个主窗口），不用旧版的网页方案（多一套 WebKit 运行时和网页↔程序的桥，旧版的 CPU 和字体坑都在那）。
  按 1280×720 设计、整体缩放到屏幕，背景铺满；背景静止，只有连接过场的准星在动。
- 字体：Space Grotesk、JetBrains Mono（SIL OFL，授权文本随字体放在 `flutter/assets/dd_kiosk/`）打进程序；中文写明 Noto Sans CJK，
  kiosk 安装包依赖 `fonts-noto-cjk`——不写明就跟系统默认字体走（测试瘦客户机上有人拷了微软雅黑、宋体）。程序里原有的字体组件
  默认联网下字体，kiosk 不用它。
- 页面（照旧版流程）：
  - 登录卡片：用户名、口令（可切明文）、失败原因、登录按钮；用户在场看过后定：不要说明文字、输入框不画下划线（浅色底块，字段名做
    框里的提示字）。记得上次的用户名，口令不落地；开机总是从登录页开始（上次没退出的令牌开机时作废）。
  - 工作站列表：旧版的卡片条（绿 = 可以连接、红 = 别人在用、灰 = 离线；别人在用和离线的点不了，自己在别处连着的可以点）、
    数字键 1–9 选、Enter 连；默认选上次连的那台；每 15 秒刷新；右上角用户标签点开「退出登录」；底部关机（先确认）。
    停在登录页或列表上 15 分钟没人碰：列表上退出登录，登录页清掉口令（公用座位，人走了别人坐下来不能用他的身份）。
  - 连接过场（准星），只显示真实的一步「打开画面」。
  - 状态卡片：掉线（倒计时自动重连同一台、已试几次）、被拒（服务端原因原文，不自动重连）、工作站那边断开；按钮「重连」「返回列表」。
  - 顶栏：标识、标语、版本、登录后的用户、中 / EN；底栏：本机设备号、服务器、版权（江苏原力）。
- 远程窗口交给状态页的原因带「被拒」标记（要票被拒、被控端不认票、没人能填的口令框）：被拒的再试也一样，不自动重连。
- 服务端（子会话1）：`GET /api/dd/workstations`（名单和发票查授权同一个函数，带 online / in_use / in_use_by_me）。
- 语言切换改的是整个程序的语言设置（和设置页同一条路），远程窗口跟着重建；悬浮球是专业窗口进程画的，下次连接才换。
- 用户在场时修掉的三处（机器检查都发现不了）：内容没放大（缩放控件放在 Center 里只拿到「最多多大」，改成铺满整屏的固定框）；
  全屏在页面建起来时设会被恢复窗口位置盖掉（挪到窗口显示之后）；文字带黄色双下划线、输入框白底白字（最外层缺 Material、
  输入框继承了程序主题的白色填充）。
- 还没做：副屏壁纸（测试瘦客户机现在只有一块屏，要先验证 GNOME Kiosk 能不能把窗口放到指定屏）；悬浮球加「关机」等专业 / 通用
  窗口菜单统一规划（用户 10-26 定）；座位上登录的安全加固（令牌绑座位公钥、短有效期、人走了断连接，K2 分析第 1–4 项，等用户定策略）。

### 通用窗口在 kiosk 下（10-26）

- 用户发现切到通用模式后窗口能最小化，最小化后找不回来（kiosk 没有任务栏、切窗口快捷键也关了）。
- kiosk 下通用窗口一开就全屏，工具栏不给「全屏 / 退出全屏」和「最小化」；工具栏的关闭（= 断开）留着。桌面版不变。
  不做「窗口被藏起来就拉回来」的兜底（用户定）。
- 其余工具栏项不动，等用户统一规划专业窗口和通用窗口的菜单。

### 座位（10-26）

- **座位不当被控端**：装了 kiosk 包的机器（包里的记号文件 `/usr/share/dreamdesk-kiosk/seat`）被控端服务不向 ID 服务器登记、
  不开直连端口和局域网发现；和网关的心跳、设备上报照旧（直接发网关，不经 ID 服务器）。`dreamdesk-kiosk off` 切回桌面不影响，
  卸掉 kiosk 包才恢复成普通设备。
  - 起因：用户问 kiosk 关了桌面还能不能被看。能——关掉的是桌面外壳，mutter 的录屏接口、桌面门户、PipeWire 都在，被控端也起在
    kiosk 会话里；之前挡住别人的只是「拿不到票」（服务端只给工作站发票、受管被控端只认票），应急票理论上能签给座位。
  - 用户想看被查看的效果：用开发应急钥签了一张连座位的票从 209.32 去连，对端身份核对不过、连接退成不加密，查看端按规定不交票、
    被控端拒绝「没带票」——推测是 root 服务登记的身份和 kiosk 会话里被控端用的不是同一份，没再追（座位本来就不该被控）。
  - 改后核对：日志「this device is a seat, no incoming connections」、dreamdesk 不监听任何端口、设备上报照常；
    209.32 带同一张应急票去连，得到「Remote desktop is offline」。
- **自动上报为座位**：上报设备信息时带 `"dd_kind":"seat"`（请求带设备签名）。服务端（子会话1）据此给待确认的设备预选「座位」，
  确认仍由管理员做；已确认的设备上报类型和登记类型对不上时只醒目标出、记流水，不自动改类型（改类型会连带删授权和座位绑定）。

### 已核对的（10-25）

- kiosk 会话里 GNOME Kiosk 提供显示配置接口：`gdctl show` 读得到显示器，`gdctl set --color-mode bt2100` 能切到 HDR、
  切回 `default` 也正常（瘦客户机 VA2723，非持久设置）——悬浮球的「HDR」开关依赖的就是这个接口。

- 0.208 新网关（s1-39ddb92）上端到端：瘦客户机和 209.32 都改连 `dreamdesk.of3d.com:8443`，座位凭设备签名问绑定、要票、连上。
  专业画面开着时服务端断开（控制台断开同一条路）：远程窗口藏着状态下交出「被 web 控制台手动关闭」后关掉，旧专业画面 90 毫秒后退出，
