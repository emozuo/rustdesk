# 打包编译（DreamDesk 产品版）

首次搭环境（代理、镜像、Flutter 补丁、vcpkg、WSL 依赖）见仓库根 `BUILD-DEPLOY.md` §0–§3，本文只写日常命令。

| 平台 | 产物 | 状态 |
|---|---|---|
| Windows 客户端 | `dreamdesk-pro.exe`、`dreamdesk-pro-<版本>-install.exe` | 脚本一条命令 |
| Linux 客户端 | `rustdesk-<版本>.deb` | 手动几步；**改名未做**（约 P0 第 5 步），带 dd-pro 打包**未实测** |
| 服务端 | `hbbs`、`hbbr` | 上游原样 |
| macOS / iOS / Android | — | 环境未搭 |

开关：`dd-pro` 专业模式，`dd-brand` 产品改名。都不开 = 上游 RustDesk。

---

## Windows 客户端

```powershell
$env:PATH = "D:\WORKPLACE\CODING\_toolchain\flutter\bin;C:\Python312;C:\Python312\Scripts;$env:USERPROFILE\.cargo\bin;" + $env:PATH
$env:ALL_PROXY = "socks5h://127.0.0.1:10808"
$env:VCPKG_ROOT = "C:\vcpkg"

cd D:\WORKPLACE\CODING\rustdesk
powershell -File dreamdesk\scripts\build-windows.ps1
# 默认带 --hwcodec --vram（与官方 Windows x64 发布版一致；专业模式的采集也要 vram）
```

- 产物：`flutter\build\windows\x64\runner\Release\dreamdesk-pro.exe`；安装包在仓库根。
- 脚本已包含 pub get → codegen → 编 Rust → 编 Flutter → 改名 → 打安装包 → 自检（有 `rustdesk*.exe` 就报错）。
- 换过 VS 版本后报 `generator ... does not match`：先 `Remove-Item -Recurse -Force flutter\build\windows`。

## Linux 客户端（本机 WSL Ubuntu 24.04）

```bash
wsl -d Ubuntu-24.04 -u root          # 一定要 root：工具链都装在 /root 下
cd /root/rustdesk
git fetch /mnt/d/WORKPLACE/CODING/rustdesk dreamdesk && git checkout -f -B dreamdesk FETCH_HEAD
git submodule update --init --recursive

. ~/.cargo/env
export VCPKG_ROOT=/root/vcpkg PATH=/root/flutter/bin:$PATH
# vcpkg.json 变了才需要：
# $VCPKG_ROOT/vcpkg install --triplet x64-linux --x-install-root=$VCPKG_ROOT/installed

(cd flutter && flutter pub get)
flutter_rust_bridge_codegen --rust-input ./src/flutter_ffi.rs --dart-output ./flutter/lib/generated_bridge.dart

# 官方 Linux 发布版的参数是 --hwcodec --unix-file-copy-paste，按需加在 --flutter 后面（未实测）
F="$(python3 build.py --flutter --print-features | tail -1),dd-pro"
cargo build --locked --features "$F" --lib --release
# build.py 自己编 Rust 时会做这步修正，--skip-cargo 会连它一起跳过，手动补上
sed -i "s/ffi.NativeFunction<ffi.Bool Function(DartPort/ffi.NativeFunction<ffi.Uint8 Function(DartPort/g" flutter/lib/generated_bridge.dart
python3 build.py --flutter --skip-cargo
# 产物：/root/rustdesk/rustdesk-<版本>.deb
```

- Linux 先**不开 `dd-brand`**：安装包里的路径、服务文件还叫 rustdesk，单开改名会对不上，等 Linux 改名一起做。
- 不要专业模式就去掉 `,dd-pro`，或直接 `python3 build.py --flutter`（上游原样）。
- 打出的包依赖较新的 glibc（见 `BUILD-DEPLOY.md` §3），老系统装不上。

## 服务端 hbbs / hbbr

```bash
cd rustdesk-server      # 本机在 D:\WORKPLACE\CODING\rustdesk-server，Windows / Linux 命令相同
git submodule update --init --recursive
cargo build --release
# 产物：target/release/{hbbs,hbbr,rustdesk-utils}
```

部署与内网直连见 `BUILD-DEPLOY.md` §4–§6。

## 专业编码验证工具（被控端 NVENC）

```powershell
cargo build -p ddpro-enc --example capture_encode --features harness --release
target\release\examples\capture_encode.exe probe        # 看显卡能不能编 4:4:4
# run / compare 用法见 dreamdesk\crates\ddpro-enc\examples\capture_encode.rs 文件头
```

必须在有人登录的桌面会话里跑；在测试机上的跑法见 `P0-实施记录.md` 第 3 步「一键复现」。

## 改代码后的编译自检（不打包，几分钟）

环境变量同上面 Windows 那段。

```powershell
cargo check --locked --features flutter                         # 上游原样
cargo check --locked --features flutter,dd-pro,dd-brand         # 产品版
cargo check --locked --workspace --exclude rustdesk-portable-packer --features rustdesk/dd-pro,rustdesk/dd-brand
```

Linux 同样三条（在 WSL 里跑）。改了 `src/flutter_ffi.rs` 要先重跑 codegen。

## 注意

- 构建会改写 `flutter/pubspec.lock`，提交前 `git checkout -- flutter/pubspec.lock`（Windows 脚本已自动还原）。
- 公司电脑上不能运行名叫 `rustdesk.exe` 的程序（IT 黑名单，会被结束并删除）；上游原样的测试版要改名再跑。
