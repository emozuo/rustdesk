# DreamDesk 选择迁移到 RustDesk 的说明

**结论**：产品规划已从「CG 行业内网专业远程桌面」扩展为「一个产品覆盖全平台、通用远程和全球外网访问」。为此选择把技术底座换成开源的 RustDesk：DreamDesk 专业模式的核心设计迁入，作为产品的「专业模式」；其余通用部分全部直接使用 RustDesk 现成的实现。

**主要原因**：
- **通用功能直接可用。** 全平台、全球外网访问、文件传输等通用功能，RustDesk 都已经现成具备，省掉这部分的开发、测试和长期维护。
- **成熟稳定。** RustDesk 是全球最受欢迎的开源远程桌面项目之一，经过大量用户在各种环境里长期使用，稳定可靠，可以完全在公司内网私有部署。
- **迁移成本低。** 只需迁移 RustDesk 没有的专业模式核心设计，范围小、边界清晰；迁移的是已经验证过的设计和经验，不是推倒重来。

研发力量因此可以集中在 CG 专业能力上，用最小的投入得到一个完整的产品。

---

## 一、背景

DreamDesk 是画质优先、同时保证低延迟的专业远程桌面。它面向 CG 行业内网云桌面场景，已在实机环境中跑通。被控端是机房里的 Windows 图形工作站（NVIDIA 显卡），制作人员在工位上用我们定型的 Linux 瘦客户机远程工作。

它解决的是 CG 制作人员最核心的诉求：**远程画面要接近物理机**。取色核对、逐像素比对渲染结果、细线和小字、柔和渐变都是日常操作，画面不可信，其它做得再好也没用。迁移之后这一点保持不变，并且是专业模式的底线。

## 二、产品规划的变化

随着业务发展，产品要服务的人群和场景在扩大，目标从一个专业工具变成一个完整产品：

| 维度 | 原定范围 | 规划目标 |
|---|---|---|
| 使用人群 | CG 制作人员 | CG 制作人员，加上日常办公、IT 运维支持、管理人员 |
| 主控端设备 | 定型的 Linux 瘦客户机 | 瘦客户机，加上 Windows、macOS 电脑，手机、平板，网页 |
| 网络环境 | 公司内网 | 内网为主，逐步支持外网，在全球任何地方都能连回公司（出差、居家、海外分支） |
| 产品形态 | 专业远程桌面 | 一个产品、两种模式：专业模式 + 通用模式 |

扩展之后，要新增的工作大头不再是画质，而是大量**通用能力**：各平台的客户端、外网穿透与中继、文件传输、账号与设备管理、移动端适配等。这些能力和 CG 画质无关，但每一样都要长期开发和维护。

在原有项目上逐项补齐这些能力，相当于重新开发一个通用远程桌面产品。而这些能力在成熟的开源项目里已经现成可用，所以选择换一个成熟的底座，把研发力量留给 DreamDesk 独有的专业能力。

## 三、选择 RustDesk 的原因

### 1. 迁移成本低：只需迁移专业模式的核心设计

只需要迁移 DreamDesk 专业模式的核心设计：

- **专业画面链路**：颜色转换、HEVC 4:4:4 硬件编码、静止后画质收敛、抗丢包的专用画面通道、主控端硬件解码和显示、颜色准确性；
- **外设**：数位板压感与倾斜、虚拟麦克风、USB 透传；
- **瘦客户机 kiosk 外壳**：开机直达远程桌面、不露系统桌面。

连接、会话、键鼠、多显示器、声音、剪贴板、登录、升级等通用部分都不需要迁移，直接使用 RustDesk 的实现（见第 3 点）。

迁移成本低、风险小，原因在于：

- **范围小。** 需要迁移的只是画面链路和外设这几个边界清晰的模块，通用部分一行都不用迁。
- **迁的是验证过的设计。** DreamDesk 在画质、颜色、抗丢包、瘦客户机显示上已经验证过的做法、参数和踩过的坑，直接作为设计输入，不需要从头摸索；原项目的实测数据可以作为验收基准。
- **RustDesk 便于接入。** 专业画面可以作为独立的一路，和 RustDesk 原有的画面链路并行、互不干扰；它的服务框架、多显示器、光标、权限、会话管理都可以直接接上，专业模式不用自己再做一套。我们的代码可以集中放在独立目录里，对 RustDesk 只留少量接入点，不打乱它原有的设计。
- **出问题有退路。** 两种模式只区分画面链路，专业模式遇到问题时可以退回通用模式继续工作，用户不会因此连不上。

### 2. 原项目没有的通用功能，直接拿来用，省掉开发

原项目专注 CG 内网专业场景，下面这些规划目标需要的通用功能，原项目或者不在范围内，或者只做了满足内网场景的部分。RustDesk 都已经现成具备，产品的通用模式直接使用：

| 功能 | 通用模式（RustDesk 现成可用） | 原 DreamDesk 项目 |
|---|---|---|
| 主控端平台 | Windows、macOS、Linux、Android、iOS、网页 | 仅 Linux 瘦客户机 |
| 被控端平台 | Windows、macOS、Linux、Android | 仅 Windows + NVIDIA 显卡 |
| 网络连接 | 内网直连；全球外网访问：ID 服务器牵线、打洞直连，打不通时走中继，中继服务器可以按需部署多台 | 仅内网直连 |
| 文件传输 | 双向传文件和文件夹 | 未涉及 |
| 远程打印 | 被控端的文档打印到主控端的打印机 | 未涉及 |
| 终端、端口转发 | 远程命令行、端口转发 | 未涉及 |
| 文字聊天、语音通话 | 会话中直接使用 | 未涉及 |
| 会话权限 | 按连接开关键盘、剪贴板、文件等；只看不控；多人同时连接 | 整机独占或共享两种 |
| 地址簿、设备列表 | 客户端内置，对接账号服务器即可使用 | 由自研网关和控制台提供 |
| 全球化语言 | 50 多种 | 未涉及 |
| 访问方式 | 无人值守访问（固定密码）、一次性临时密码；按设备 ID 或 IP 连接；局域网内自动发现设备 | 经网关 AD 账号登录后分配机器 |
| 受限网络 | 支持 Socks5 / HTTP 代理和 WebSocket 连接，限制较多的网络里也能连通 | 未涉及 |
| 网络唤醒 | 远程把关机的电脑开起来 | 未涉及 |
| 账号安全 | 双重认证（2FA）、受信任设备管理；IP 白名单、ID 白名单 | 依托 AD 域账号 |
| 隐私模式 | 远程操作时被控端屏幕黑屏、屏蔽被控端本地键鼠，旁人看不到操作内容 | 未涉及 |
| 会话录像 | 可自动录下所有接入的会话，便于审计 | 未涉及 |
| 远程重启 | 支持 | 未涉及 |
| 编码格式 | H.264、H.265、VP8、VP9、AV1，显卡硬件编解码，自适应码率 | 只有 HEVC 4:4:4（专业画质） |
| 免安装运行 | 不安装也能直接运行，临时协助方便 | 未涉及 |

除了上表，RustDesk 还有这些必要的功能，通用模式同样直接可用：

- 连接需被控端确认，可在确认时一并提权，处理需要管理员权限的操作；会话结束自动锁屏；
- 远程调整被控端分辨率，画面按窗口自适应缩放；虚拟显示器，没有接显示器的机器也能远程；
- 多显示器：每块屏一个窗口，或者用上本机所有屏幕；
- 跟随远程光标和窗口焦点；键盘支持映射和翻译两种模式；相对鼠标模式适合三维软件和游戏；
- 远程锁屏、发送 Ctrl+Alt+Del；一键截图；远程查看被控端的摄像头；
- 剪贴板同步，包括直接复制粘贴文件；
- 地址簿支持标签、分组和备注，设备多了也好管理；
- 自动检查和下载新版本；
- 多个远程会话以标签页方式打开，明暗两种主题。

这些功能都是现成、经过大量用户检验的。每一项如果自己开发，都要分别适配各个平台、在各种环境里反复测试、长期跟进系统更新；直接使用，开发、测试和维护的投入都省掉了，质量风险也大幅降低。

### 3. 原项目自研的基础部分，改用成熟实现，减少维护

原项目里有一批和画质无关、但每个远程桌面都必须有的基础部分，过去都是自己开发、自己维护。RustDesk 有成熟的同类实现，改用之后这些代码不再需要我们单独维护：

- 连接与会话管理：控制协议、会话生命周期、鉴权；
- 被控端进程结构：服务、控制台代理、采集代理、输入助手等多个进程的协作，改为 RustDesk 的单一后台服务；
- 键鼠注入，锁屏、登录界面、UAC 弹窗下的桌面跟随，Ctrl+Alt+Del；
- 多显示器布局、光标同步、扬声器声音、分辨率调整；
- 登录界面和启动程序；
- 网关里自有的登录、心跳、机器列表、升级协议：改为实现 RustDesk 的接口（见第 7 点）。

这些基础部分最容易在各种系统环境下出兼容问题，也最耗测试精力。改用成熟实现后，研发、测试和维护的精力可以全部留给专业画质、外设这些真正的差异化能力。

### 4. 成熟稳定、可靠，省去大量测试成本

RustDesk 是全球最受欢迎的开源远程桌面项目之一，已经持续开发多年，社区规模大、贡献者多、更新活跃。

- **稳定可靠。** 大量用户在各种操作系统、显卡、网络环境下长期使用，常见的兼容性问题、稳定性问题和异常情况（断线重连、锁屏切换、显示器插拔、分辨率变化等）大多已经在社区里被发现和修复。在它的基础上开发，等于直接继承了这些年积累的稳定性。
- **省去测试成本。** 远程桌面最难的是兼容性：操作系统版本、显卡和驱动、显示器配置、网络环境的组合非常多，每一种都可能出问题。自己开发的功能，要逐一搭建测试环境、长期反复回归验证；RustDesk 的通用功能已经在大量真实用户的各种环境里跑过，问题由社区持续发现和修复，官方还在 Windows、macOS、Linux 上自动构建并运行测试。每次合并官方更新后，本地跑一遍现成的测试即可，测试力量只需集中在专业模式和我们自己改动的部分。
- **问题有人一起修。** 遇到的问题很多别人已经遇到过，社区里有现成的讨论和修复；我们发现的通用问题也可以反馈给社区，不需要独自承担所有排查工作。

### 5. 安全可控

- **可以完全私有部署。** 服务端（ID 服务器、中继服务器）同样开源，可以部署在公司内网，连接数据不经过任何第三方。
- **连接加密。** 经 ID 服务器建立的连接端到端加密；专业模式的画面通道也按同一水平独立加密。
- **语言层面更安全。** RustDesk 用 Rust 语言编写，从语言层面避免了大量内存安全类缺陷，这类缺陷是远程桌面软件崩溃和安全漏洞的常见来源。
- **源代码完全可见。** 所有代码都可以审查，不存在黑盒。

### 6. 持续获得开源社区的成果

RustDesk 由开源社区持续迭代。计划每月合并一次官方更新，安全修复随时合入，新平台适配、新功能、问题修复都能直接用上。由于我们的代码集中在独立目录、对官方代码只留少量接入点（见第 1 点），每次合并的工作量很小。

### 7. 账号和设备管理可以对接公司现有体系

RustDesk 客户端已经内置登录、地址簿、设备列表的接口。网关改为实现这套接口、后端对接公司 AD 域账号后，登录和设备列表即可直接使用，客户端不需要改动。

## 四、迁移后的产品：一个产品、两种模式

| | 专业模式（迁入的 DreamDesk 能力） | 通用模式（RustDesk 原有能力） |
|---|---|---|
| 适用场景 | CG 制作：建模、贴图、灯光、审片、合成、调色 | 日常远程、IT 运维与协助（可替代 VNC）、移动端、全球外网访问 |
| 色度与编码 | HEVC 4:4:4 全色度，显卡硬件编解码 | 硬件编码只支持 4:2:0 色度 |
| 静止画质 | 画面停下后快速收敛，细节还原到接近原图 | 停下后再编几十帧变清楚，仍是有损压缩 |
| 10bit / HDR | HDR 桌面用 10bit 传输 | 不支持 |
| 画面传输 | 专用画面通道，丢包快速恢复 | 所有数据走同一条可靠连接，没有专门的画面通道 |
| 数位板 | 压感与倾斜 | 不支持 |
| 麦克风 | 主控端的声音进入被控端的麦克风设备，录音、会议软件直接可用 | 有语音通话，声音只在被控端播放 |
| USB 透传 | 支持 | 不支持 |
| 瘦客户机 kiosk 模式 | 开机直达远程桌面，不露系统桌面；屏蔽系统快捷键；程序异常自动恢复；无人值守升级 | 不支持，作为普通应用程序运行 |

两种模式只在「画面怎么编码、传输、显示」上不同；第三节第 2 点里的通用功能，以及连接、键鼠、光标、多屏、声音、剪贴板、加密、权限，两种模式全部共用；数位板、麦克风、USB 透传两种模式也都能用。对用户是同一个安装包、同一个入口，制作时用专业模式，其它场景用通用模式，会话中可以一键切换。对运维是一套客户端、一套服务器、一个账号体系。

**两种模式可以同时连同一台机器，互不影响画质。** 制作人员用专业模式工作时，运维、组长等其他人可以同时用 RustDesk 通用模式连上同一台机器查看或协助，这就是多人共享远程桌面。专业模式的画面是独立的一路，不和通用模式共用编码器，所以不会因为有人同时在看就降低专业模式的画质；通用模式这一路由被控端另外采集，流畅度比专业模式低一些，用来查看和协助足够。

这一点优于 ToDesk 等常见远程软件。常见的做法是多人连同一台机器时共用一路画面编码，画质按网络和设备条件最差的一方来定，实际使用中会出现「有人一起看，主用户的画面就变差」的问题。迁移后的产品里，多人共享时其他人走的是 RustDesk 通用模式，和专业模式是两条互不相干的画面链路：专业模式用户的画质只由它自己的链路决定，有多少人同时在看都不降画质。

**通用模式可以替代 VNC。** 机房工作站的远程查看、运维和协助，直接用通用模式即可：同一套客户端和账号体系，连接加密，还带文件传输、多平台主控端和全球外网访问。不用再另外部署和维护一套 VNC。

## 五、需要关注的事项

- **开源许可证。** RustDesk 采用 AGPL-3.0 许可证，产品对外分发或提供服务时有相应的开源义务，需要按公司规定评估和处理。
- **上游跟进。** 每月合并一次官方更新，需要固定的少量维护投入；按第三节第 1 点的代码组织方式，这部分成本可以压到很低。
