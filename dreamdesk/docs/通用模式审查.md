# 通用模式审查（对 RustDesk 原有文件的改动）

目的：不开 DreamDesk 的开关（`dd-pro` / `dd-brand` / `dd-managed`）编出来的程序，行为和原版 RustDesk 一致。
所以每处对原有文件的改动，要么被开关包住、关掉时原代码原样保留，要么关掉时和原版等价。**每次合并上游、大改之后重跑一遍。**

## 怎么跑

```sh
B=$(git merge-base dreamdesk upstream/master)
git diff --numstat $B dreamdesk -- . ':!dreamdesk' ':!src/ddpro' ':!src/lang'   # 改了哪些原有文件
git diff -U3 $B dreamdesk -- <文件>                                               # 逐个看
```

先看「改了原有行」的（numstat 第二列不为 0），再看纯新增里有没有不在开关下的。查完两种都编一遍：
Windows `cargo check --lib --features flutter,hwcodec,vram`（不开）和加上 `dd-pro,dd-brand,dd-managed`（开）；
Linux 在 WSL 编译副本里同样两遍（只在 Linux 编的代码，Windows 上查不到）。

这三处也是给上游提 PR 的候选（都是原版的毛病）。

关掉开关时和原版等价、不用改的：`libs/scrap/src/dxgi/mod.rs` 新字段默认关；`libs/portable/src/main.rs` 进程名常量不开 `dd-brand`
时就是原字符串；`src/platform/windows.rs` 安装脚本里多出的一行不开时是空行；`handle_voice_call` 拆开的判断不开时等价；
几处 `pub(crate)` 只改可见性；Flutter 的专业模式提示只在收到专业模式事件时显示，平时是不占位置的隐藏部件。

**有意的差异**（产品版要的，都在 `dd-brand` / `dd-pro` 下）：产品名和内网服务器、不探测公网 STUN；强制关「新连接在标签页中打开」；
默认开「将我的所有显示器用于远程会话」；受管模式（`dd-managed`）下的连接授权、设备签名、证书固定、克隆自查。

## 2026-10-27 夜（10-26 审查之后的 17 个提交，8d89ff322..ee984170e）

当天主要是受管版界面按 UU 换装，以及单一受管版。对比的是 RustDesk 原有文件，不含 `dreamdesk/`、`src/ddpro/`、`src/lang/` 和新加的 `dd_*.dart`。
共 27 个原有文件：Rust 7 个、Flutter 原有文件 15 个，另有 `Cargo.toml`、`build.py`、`pubspec.yaml`、`message.proto` 和两张壁纸。
相对上游合并基点 1297da6d1 的累计改动是 58 个文件、+1302 / −99。

**没查出漏包的**：
- Rust 的改动都在 `dd-pro` 的 `cfg` 下：
  - `video_service.rs` 视频上报；
  - `display_service.rs` 显示器型号，只在 `dd-pro` 且 Windows 时生效；
  - `io_loop.rs` 记连接时刻；
  - `flutter.rs` 给屏幕列表加型号；
  - `flutter_ffi.rs` 的 `dd-net-stats`。
- Flutter 原有文件的钩子都包在 `kDdManaged` 里。`kDdManaged` 由 Rust 的 `dd-managed` 选项决定，不开开关时为假。

两种配置都编过了（当晚补跑，target 用 `_toolchain/ddpro-test/target-clippy` 和 WSL 的 `/root/target-check`，不碰仓库和编译副本自己的 target），**四遍都通过**：
- Windows：`cargo check --lib --features flutter,hwcodec,vram`，以及再加 `dd-pro,dd-brand,dd-managed` 的一遍。两遍都是 11 条警告、内容相同，都在上游代码里，没有落在我们改的行上。
- Linux（WSL 编译副本，先 `wsl-sync.sh` 对齐）：`build.py --print-features` 给的 `hwcodec,flutter`，以及再加 `dd-pro,dd-brand,dd-managed` 的一遍。两遍警告数都是 117 条（主库 106 条），逐条按 `git blame` 查过，没有落在我们提交的行上。

**关掉开关时和原版等价、不用改的**：
- `message.proto` 的 `DisplayInfo.dd_label = 1000`：不开开关时从不赋值，空串在 proto3 里不上线。`DisplayInfo` 的构造都带 `..Default::default()`。
- `model.dart`：`Display.ddLabel` 和切屏时沿用型号那一行不包开关，不开开关时恒为空串。沿用那一行访问 `_pi.displays[display]`，紧接着的原有一行也这样访问，越界时两边一样抛错。
- `terminal_mouse_handler.dart` 新加的 `theme` 参数：没传时给 `TerminalThemes.defaultTheme`，和 xterm 4.0.0 `TerminalView` 的默认值相同。
- `file_manager_page.dart` 窗格多出的 `decoration: ddFtPaneDecoration`：不受管时为 null。那个 Container 没有 `color`，不冲突。
- `pubspec.yaml` 把 `desktop_multi_window` 换成 `dreamdesk/third_party` 里的副本：
  - 只多了 `setMinimumSize`，唯一的调用点在受管钩子 `ddOnRemoteWindowCreated` 里；
  - Windows 的 `WM_GETMINMAXINFO` 在没设最小尺寸时 `break`，照原样交给默认处理。
- `pubspec.yaml` 多登记的 `assets/dd/`：两张壁纸共约 120 KB，两种构建都打进去，不影响行为。
- `port_forward.rs` 的口令登录测试：只在 `dd-managed` 下不编，不开开关时照常编、照常跑。
- `ddpro_mode_badge.dart`：徽标换了样子，回到窗口时重读质量监测。只在收到专业模式事件时才显示，这类事件只有 `dd-pro` 构建会发。
- `Cargo.toml` / `build.py`：删了 `dd-managed-dev`，不影响不开开关的构建。
- `desktop_setting_page.dart`：10-26 加的「显示」页置灰、说明已经撤掉，那段和上游一字不差。

**有意的差异**（都只在受管版，即 `kDdManaged` / `dd-managed` 下）：
- **设置页**：
  - 藏「账户」分类，登录入口只有首页的域账号登录；
  - 页头、分类列表、卡片、开关行、按钮、解锁提示换装。
- **控制中心**：非 Linux 主控端不放「切到专业模式」。专业窗口、硬解、直接上屏都只按 Linux 写了。
- **全局主题**：`main.dart` 用 `ddLightTheme()`，固定浅色。
- **对话框类**：消息框、轻提示、对话框按钮、下拉框、截图对话框、重启确认的图标都换装。
- **远程窗口**：
  - 滚动条换样子、一直显示；
  - 标题栏是照 UU 的标题栏（`kDdTabBarHeight`）；
  - 文件传输、端口映射、终端这些子窗口的标签栏换成 `DdSubWindowBar`。
- **多屏**：
  - 「将我的所有显示器用于远程会话」只在连接的主窗口铺开；
  - 拖出去的屏由 `ddHandleRemoteWindowCall` 处理报到和归还；
  - 远程窗口有最小尺寸。
- **质量监测**：原型的样子，用中文名称。
- **各页换装**：
  - 文件传输页（同时去掉传输卡片的大圆角）；
  - 端口映射页；
  - 连接管理窗口（`server_page.dart` 的头部、权限、按钮）；
  - 终端主题和不透明背景。

`server_page`、`port_forward_page`、`file_manager_page` 三处钩子拷贝了上游的调用，已记在 `合并上游检查清单.md` 第 1 节。
